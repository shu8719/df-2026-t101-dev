# 精度の実験

> **このドキュメントで決めたこと**
> 1. 同じ動画から、手の甲の4区間の長さを「ノギス（正解）」「1円玉の方法」「AIの方法」の3つで出して比べる。11/9 の精度の検証（[measurement.md §10](../measurement.md#10-精度の確かめ方)）で撮る手を使えれば理想。
> 2. 合格の目安は、ノギスとの差（倍率のずれ）が、全部の撮影の中央値で2%以内、最大で4%以内。
> 3. 全体のフレームで推定する場合と、手を切り抜いたフレームで推定する場合の両方を試す。本番で `hand-mesh` に載せられるかを決めるため。

関連：[README.md](README.md)、[method.md](method.md)

---

## 1. 用意するもの

| もの | 使い道 |
|---|---|
| スマホ（機種名を記録する） | 撮影。焦点距離（35mm換算）を調べておく |
| 1円玉 | 1円玉の方法と比べるため、一緒に写す |
| ノギス | 正解の長さを測る |
| 手元のPC（GPU） | AIを動かす |
| 協力するメンバー3人以上 | 自分の手を撮る（実験に使うことに同意した人だけ。[method.md §6](method.md#6-プライバシーの扱い)） |

## 2. 手順

1. **正解を測る**：握った形のまま、手の甲の4区間をノギスで測る（測り方は [measurement.md §10.1](../measurement.md#101-測るものと道具) と同じ）。区間ごとに2回測り、平均を正解にする
2. **撮る**：本番と同じ撮り方（手の甲を上にして机に置き、1円玉を横に置いて、5〜10秒で半周。[measurement.md §2](../measurement.md#2-撮影の手順)）で、1人3回撮る。カメラから手までのおおよその距離も記録する
3. **1円玉の方法**：同じ動画を、アプリの「動画ファイルを選ぶ」で読み込ませ、採寸の JSON から手の甲の4区間の長さを取る
4. **AIの方法**：同じ動画を実験のスクリプトにかけ、手の甲の4区間の長さを出す（[method.md §1](method.md#1-流れ)）
5. **比べる**：区間ごとの差と、倍率のずれ（§4）を表に書く

## 3. 比べる条件

| 条件 | 中身 | 何が分かるか |
|---|---|---|
| A 全体・焦点距離もAI | フレーム全体を入れ、焦点距離もAIに推定させる（Depth Pro） | ブラウザで動かす場合に近い精度 |
| B 切り抜き・焦点距離もAI | 本番で `hand-mesh` に送るのと同じ切り抜き（21点を囲む四角を20%広げ、長い辺512px）を入れる | `hand-mesh` に載せられるか |
| C 全体・焦点距離を与える | 機種の焦点距離から計算した値を与える | 焦点距離が分かれば、どこまで当たるか（上限の目安） |

- 条件Bでは、切り抜きの位置と縮小の割合から、元の画像の焦点距離に換算して比べる
- 時間があれば、Depth Pro 以外の候補（[method.md §3](method.md#3-候補のモデル)）でも同じことをする

## 4. 比べ方

区間 s ごとに、比 `r_s = AIで出した長さ ÷ ノギスの長さ` を出す。本番の倍率と同じように、4区間の中央値を「その撮影の倍率のずれ」とする。

```
ずれ（%）= (median(r_s) − 1) × 100
```

- 1円玉の方法も同じ式で出し、AIの方法と並べる
- ずれがいつも同じ向き（たとえば、いつも4%短い）なら、補正係数で直せる（[method.md §2](method.md#2-精度の見積もり)）。そのため、**補正する前と、全体の平均で補正したあと**の両方を書く。ただし補正係数は、ほかの人の撮影で確かめないと当てにならない（人数が少ないので、1人を除いて求めた係数を、その1人に当てはめて確かめる）

## 5. 合格の目安

| 項目 | 目安 | 理由 |
|---|---|---|
| ずれの中央値（全部の撮影） | 絶対値で2%以内 | すき間1.5mm、こぶしの幅約80mmから（[README.md](README.md#一番の心配精度)） |
| ずれの最大 | 絶対値で4%以内 | 1回でも大きく外れると、食い込む形ができる |
| 同じ人の3回のばらつき | 2%以内 | 撮り直しで結果が変わると使えない |

- 目安は案で、チームで決め直してよい
- 3人×3回＝9回なので、数は少ない。合格でも「この人数では」と書く
