# AIの距離推定で手を実寸にする（1円玉がないとき）

> **このドキュメントで決めたこと**
> 1. 1円玉など長さの分かる物がないときの方法として、写真から実際の距離を推定するAI（単眼メトリック深度推定）で、手の甲の4区間の長さ（mm）を出せるかを確かめる。
> 2. これは**実験**で、MVP には入れない。本番の流れ（1円玉で実寸にする）と仕様書（`docs/` の各章）は変えない。作業は `exp/depth-scale` ブランチで行う。
> 3. 精度が合格の目安（ノギスとの差が中央値で2%以内、最大で4%以内）を満たしたら、仕様（`measurement.md` §9 フォールバック）に足すかをチームで決める。満たさなければ、1円玉の測り間違いの確かめ用にするか、ピッチで今後の課題として話す。

## なぜやるか

- 実寸にする倍率 k は手全体で1つの数字で、手の甲の4区間（0→5、0→9、0→17、5→17）の「測った長さ ÷ メッシュの長さ」の中央値で決めている（[measurement.md §8.2](../measurement.md#82-メッシュの合成と実寸化)）
- つまり、**手の甲の4区間の本当の長ささえ分かれば**、1円玉がなくても、それ以降の流れ（メッシュの実寸化・カバーの殻・クリップ）はそのまま使える
- いまの代わりの方法（写真2枚のモード）も1円玉が要る。1円玉が手元にない人や、検出に失敗したときの手段がない

## 一番の心配：精度

- カバーは、こぶしとのすき間 `HAND_CLEARANCE_MM` = 1.5mm（仮）で作る
- こぶしの幅を約80mmとすると、大きさのずれは**約2%（1.6mm）以内**に抑えたい。これより大きくずれると、カバーが手に食い込む（安全の決まり R6e）か、手の上で回る
- 大きさのずれの割合は、**距離のずれの割合とほぼ同じ**になる（[method.md §2](method.md#2-精度の見積もり)）。カメラから手まで約30cmなら、距離を約6mm以内で当てる必要がある。これはかなり厳しい
