キックオフ資料の p.42 より。8 項目をそれぞれ 0〜3 点、合計 24 点。テーマは「Own the Why, Build with Intent.」（AI まかせにせず、技術を選んだ理由・よい点と悪い点・捨てた案を自分の言葉で語る）。

| 2a 課題解決に必要な操作が一連の流れとして動くか | 4（デモ） |

## 2. スライドごとの中身と原稿

### スライド 1：タイトル（10 秒）

- 画面：「自助具 / **ジェネレーター**」、「こぶしを撮るだけで、その人の手に合う自助具を 3D プリント」、ロゴの下に「チーム ○○ ｜ DevFest Hackathon 2026（医療・福祉）」
- 原稿：
  > 「チーム○○です。スマホでこぶしを撮るだけで、その人の手に合う自助具を 3D プリントできる Web アプリ『自助具ジェネレーター』を作りました。」

### スライド 2：課題（30 秒）

- 画面：見出し「指が握った形で固まると、筆もスプーンも持てない」、本文（誰が困っているか・なぜ作れないか）、黄色のカードに **4.4%**（3D プリンタを使ったことがある作業療法士、3,469 人中 153 人）、出典
- 出典：Harada Y ら, Disabil Rehabil Assist Technol 2025;20(8):3162–3176
- 原稿：
  > 「病気やけがで、指が握った形のまま固まってしまう人がいます。そうなると、筆やペン、スプーンを自分で持つことが難しくなります。道具を持つための『自助具』は、手の形が人それぞれなので、一人ずつ合わせて作る必要があります。3D プリンタなら作れますが、作業療法士の調査では、使ったことがある人は 4.4% だけ。理由は『職場に設備がない』『使い方がわからない』でした。」

### スライド 3：何を作ったか（20 秒）

- 画面：見出し「撮るだけで、手に合うカバーとクリップができる」、3 列「① こぶしを撮る」「② AI が部品を組む」「③ 確認して刷る」
- 原稿：
  > 「私たちのアプリでは、1 円玉と一緒にこぶしを動画で撮るだけで、手の形を mm 単位の 3D にします。そこからこぶしにかぶせるカバーと、筆を挟むクリップを Gemini が組み立てます。ただし Gemini には形そのものは作らせません。最後に作業療法士が確認して、3D プリントします。では、デモをご覧ください。」

### スライド 4：デモ（75 秒）

- 画面：赤の全面に「デモ」「撮影から印刷データまで（75 秒）」。Google Slides でデモ動画を埋め込む
- 原稿（動画に合わせて話す）：
  > 「まず、やりたいことを選びます。今回は『筆で字を書きたい』、筆の太さは 8mm です。
  > 次に、1 円玉を横に置いて、こぶしをスマホで半周撮ります。手の骨組みが重なって、写っているかがその場でわかります。1 円玉は自動で見つかります。
  > 撮った動画から、手の 3D ができました。大きさは 1 円玉で mm に合わせています。
  > ボタンを押すと、Gemini が部品を選んで寸法を決めます。カバーは手の面に沿って作られ、筆を挟むクリップの角度も、決めた理由と一緒に出てきます。角度はここで選び直せます。
  > 最後に、印刷用のデータをダウンロードします。こうして刷ったのが、こちらです。」
  （最後の一文で、実物を手に持って見せる）

### スライド 5：Google 技術の活用（30 秒）

- 画面：見出し「どの Google 技術も、外すと流れが止まる」、構成図（簡略版。黒い太枠が Google の技術）、右に 4 項目
  - Gemini 4 Argon：部品選び・寸法・理由・画像での確認。外すと、要望を形にできない
  - MediaPipe：端末の中で手の 21 点を取る。外すと、本人に合わせられない
  - Cloud Run：OpenSCAD で形を作り、GPU で手の 3D。外すと、刷れる形にならない
  - Firebase：ルールで、確認前の印刷データを守る。外すと、安全の約束を守れない
- 原稿：
  > 「仕組みです。手の点は MediaPipe でブラウザの中で取るので、動画はサーバーに送りません。Gemini は部品を選んで寸法と理由を出し、Cloud Run の OpenSCAD がそれを刷れる形にします。作業療法士の確認が済むまで印刷データを渡さないことは、Firebase のルールで守っています。どれか1つを外すと、この流れは成り立ちません。」

### スライド 6：Own the Why（30 秒）

- 画面：見出し「Own the Why：AI に形を作らせない、と決めた」、3 列（選んだ案と捨てた案）、下に「設計の判断 13 件を ADR に残している」

| 決めたこと | 選んだ案 | 捨てた案と理由 |
|---|---|---|
| 形の作り方 | Gemini は部品と寸法を JSON で出すだけ | 生成 AI で形をまるごと作る → 寸法を保証できない（先行研究でも中心的な課題） |
| 採寸 | ブラウザの中の MediaPipe ＋ 1円玉 | 写真を AI に送る → 写真が外に出る／3D スキャナー → 職場に設備がない |
| 実行基盤 | Cloud Run（使わない間は 0 台） | Cloud Run functions → OpenSCAD を同梱しにくい／仮想マシン → 常に費用がかかる |

- 原稿：
  > 「一番大きな判断は、AI に形を作らせないことです。生成 AI で形をまるごと作ると寸法を保証できず、先行研究でもそれが中心的な課題でした。採寸は手の写真を外に出さないためにブラウザの中で行い、実行基盤は OpenSCAD をそのまま動かせて使わない間は費用がかからない Cloud Run を選びました。こうした判断 13 件を、理由と捨てた案と一緒に記録しています。」

### スライド 7：安全性・拡張性（20 秒）

- 画面：左「安全：かぶせるだけ」、右の緑のカード「プライバシーと拡張性」
- 原稿：
  > 「安全のため、カバーは『かぶせるだけ』にしました。手のひら側は開け、手首は覆いません。これは AI ではなく、描いたあとの形をプログラムで検査しています。手の動画は保存せず、AI に渡すのは数値と文だけです。部品は 1 か所で管理しているので、ペンやスプーンのクリップも足せます。」

### スライド 8：結果とこれから（15 秒）

- 画面：大きな数字「○mm」、「採寸の誤差（メンバーの手・11/9 の検証）」、下に「これから」
- 原稿：
  > 「実際に刷って、メンバーの手で確かめました。採寸の誤差は ○mm でした。これからは、ペンやスプーンのクリップを増やし、指が固まった方と作業療法士の方に使ってもらいたいと考えています。」

### スライド 9：結び（5 秒）

- 画面：引用の形で「Own the **Why**, Build with **Intent**.」、「ありがとうございました ｜ チーム ○○」
- 原稿：
  > 「ありがとうございました。」

## 3. デモ動画の絵コンテ（75 秒）

| 秒 | 画面 | 見せたいこと | 撮り方のメモ |
|---|---|---|---|
| 0–8 | やりたいこと | 「筆で字を書きたい」「筆の太さ 8mm」を選ぶ | タップを速めに。待ち時間は切る |
| 8–25 | 撮影 | 1 円玉を置き、こぶしを半周撮る。骨組みが重なる | スマホの画面録画と、外から撮った映像を左右に並べると伝わりやすい |
| 25–30 | 1円玉の確認 | 1 円玉が自動で囲まれる | — |
| 30–40 | 採寸結果 | 手の 3D が回る。mm の数字 | 解析の待ち時間は早送り（「早送り」と字幕を出す） |
| 40–62 | 生成とプレビュー | カバー＋クリップ＋筆の 3D を回す。AI の理由の一覧。角度を 70→60 度に変える | 生成の待ち時間は早送り。理由の文が読める大きさでズーム |
| 62–70 | ダウンロード | 印刷用 STL をダウンロード | 「デモ用：OTの確認を省略しています」の表示が映ってよい（むしろ映す） |
| 70–75 | 実物 | 刷ったカバーとクリップを着けて筆で書く | 実物は 11/10 朝の最終版で撮る |

- 解像度は 1920×1080。文字が小さい画面はズームする
- 撮影は `settings/runtime.demo_mode = true` の間に行う

## 4. 決めてほしいこと・確かめること

| 項目 | 状態 | メモ |
|---|---|---|
| チーム名・プロダクト名 | 要確認 | スライド 1・9 が「チーム ○○」のまま。「自助具ジェネレーター」はまだ仮称 |
| 採寸の誤差の値 | 11/9 の検証で決まる | スライド 8 が「○mm」のまま。推測で埋めない |
| 「曲がったまま固まった指」での検証 | まだしていない | 言えるのは「メンバーの手で確かめた」まで（`docs/prior-art.md` §3 の注意どおり） |
| デモ動画に音声を入れるか | 要相談 | 案は「音なし＋会場で話す」。会場の音響が不安なら、字幕を必ず入れる |
| 実物の写真 | 11/10 朝に撮る | テンプレートには写真を入れる型の表紙もある。写真ができたら差し替えられる |
| Google Slides での見た目 | 未確認 | pptx を取り込んだあと、Google Sans と日本語の折り返しを確かめる |
| クリップの角度 | 60／70／80 度 | 2026-11-08 に 0／20／40 度から変えた（`scad/catalog.json`）。ADR-0013 はまだ古い値 |
